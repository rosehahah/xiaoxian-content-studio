# 正文路线与内置替代规则

只有对应外部入口实际可读，才记录为已使用 skill。名称相似、链接存在或机器上有 CLI，不等于本期已调用；参考上游原则时记录为“规则参考”，不是独立 skill 执行。用户已配置的写作方法优先，缺失时用下面的项目原创简明规则完成可审阅稿件。

## 经验教程

先回答读者做完能获得什么，再用真实成品展示结果。解释开始条件、需要的输入、关键操作、实际输出与成功检查；容易失败的环节补排错或范围说明。示例应来自真实材料，适当截图、图注、操作 GIF 和可复制提示词承担功能，不用装饰图代替证据。

代码存在写成“代码实现/待实测”，官方文档支持写成“文档支持”，用户估计用时写成“作者亲述约……，包含……，不含……”。操作建议不能改写为作者当时已完成的步骤；没有读者反馈就不能补效果或因果。

开源版教程从当前发行包验证安装、环境与可打开的成品。当前尚未验证时保留待核验项，不编造“三分钟上手”、全部 Agent 兼容或无需依赖。

## 真实创业日志

保留具体事件、当时面临的选择、实际行动、尚未解决的问题和作者已有的感受。没有辞职原料就写已有创业事件，不补辞职日期、裸辞天数、收入、客户、戏剧化对话与情绪经历。反思可以是作者确认后的判断，不能伪装为客观效果。

用户要求 Viral Writer + 中文 Humanizer 时，正文先由可用 Viral Writer 入口组织，再做自然化编辑。若 Humanizer 仅能通过已有工作流、命令或明确版本参考规则完成，准确记录实际路径；不要说独立中文/英文 skill 已安装。不要因使用备用自然化规则而强套经验教程的完整结构。

## 自然化编辑的项目规则

删泛泛开场、模板转折、重复结论和无证据的夸张词。用具体动作、对象与真实例子表达，长短句按实际意思安排；保留作者原本的语气、犹豫与限制。术语帮助理解时解释它，不为了“口语化”删掉必要条件。

逐项对照事实记录再交付，尤其检查“建议”是否变成“我做了”，“亲述估计”是否变成“独立计时”，“做出成品”是否变成“带来增长”。不能删除合规的 AI 声明、冒充纯人工创作、承诺绕过检测，或用检测分数证明写作质量。

## 最小方法记录

在编辑说明中记录正文路线、实际 skill/参考入口与版本、来源清单、关键限制、做过的检查和仍未执行的检查。说明应简短，放在编辑交付里，不把内部实现细节塞进读者正文。
